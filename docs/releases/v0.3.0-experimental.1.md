# v0.3.0-experimental.1 — Development Source Snapshot

Draft GitHub Release body (2026-10-21). Tag target: the v0.3 development source baseline on the
`docs/v03-source-release-scope` branch. This is an **Experimental development source snapshot** — a
record of v0.3 development work. It is **not** a stable runtime release, ships **no official
installers**, and promises **no** out-of-the-box use, general security sandbox, or production
readiness. The only formally released stable baseline remains **v0.2.0**. The v0.3 full runtime
security acceptance is still **BLOCKED** (details below).

Mark this release as **Pre-release** on GitHub.

## What is new in the v0.3.0 development source

- Two-support overhung shaft statics: signed one-plane and signed two-plane point-load models
  (`two_support_overhung_signed_point_load_v1`, `two_support_overhung_two_plane_point_load_v1`) with
  Reviewer gates and Engineering Model Cards; the registry grows from seven to nine models.
- `verified_overhung_two_plane_shaft_strength_chain_v1`: an explicit opt-in verified overhung screening
  workflow with bound Reviewer evidence, original-request binding, four-model provenance, and exact
  Verified Handoff. It requires explicit acceptance of constant torque over the shaft and is not an
  automatic equivalent of the old simply supported two-plane tool.
- A bounded Windows supervisor for the overhung workflow: Job-based committed-memory quotas
  (512 MiB/Job, 256 MiB/process), a 16-process limit, a single-execution budget with cooperative
  timeouts, and fail-closed reclamation (`REAP_FAILED`/`BLOCKED`).
- A new string transport for the overhung tool: a closed `{request_json}` / `{response_json}` envelope
  that preserves negative zero and binary64 values end to end. The old numeric transport remains
  affected by KI-NUM-002.
- Documented input, supervisor and transport contracts
  ([P1A](../PHASE_14C_P1A_INPUT_CONTRACT.md), [P1B](../PHASE_14C_P1B_SUPERVISOR_CONTRACT.md),
  [P1C](../PHASE_14C_P1C_NATIVE_TRANSPORT_CONTRACT.md)) and the
  [overhung workflow reference](../VERIFIED_OVERHUNG_SHAFT_WORKFLOW.md).
- New explicit entry `start-mechanical-overhung-dsh.cmd` (isolated temporary `DSH_HOME`, no HTTP server,
  telemetry disabled, empty-input/EOF cancels without a model request) and
  `scripts/verify_p1c_runtime.mjs` for real mounted-inventory verification of the default 11-Tool and
  explicit 12-Tool profiles.

## Scope of the existing independent acceptance records

C2 verified, under pre-existing trusted dependencies on the recorded Windows machine: a clean source
archive of the tracked tree; an isolated editable source install (metadata 0.3.0); a from-source plugin
rebuild; real runs of the three default engineering operations and the explicit 12-Tool
supervisor/workflow/reviewer/provenance/lineage/handoff operations, including signed-zero roundtrip and
fail-closed scenarios; and session tool restore 11 → 12 → 11. P1C real-inventory verification passed
28/28 on recheck, with the first run's 9 Junction-EPERM failures retained on record. These records apply
only to the executed source paths on that machine; they do not extend to arbitrary providers, Web UI
sessions, fresh machines, or any packaged installation.

## Not supported

Distributed loads, applied couples, axial loads, fatigue, stress concentration, automatic material
selection, production diameter selection, deflection, critical speed, bearing selection, gear/belt load
generation, CATIA, and CAE are outside the verified workflows. `d_min` is a theoretical minimum strength
diameter, not a production diameter.

## Runtime dependency note

The DSH runtime, DSH Tools, and the Win32 process provider remain pinned to **0.2.0-rc.2**. This
snapshot does **not** update DSH. The project and plugin versions are 0.3.0; project and runtime version
numbers are not interchangeable.

## No installers, no product promises

This release provides no wheel, sdist, or npm package as a complete agent installation (see KI-DEP-003).
Deployment is a full source checkout plus local editable install and local plugin build, per
[docs/V0_3_SOURCE_ONLY_DEPLOYMENT.md](../V0_3_SOURCE_ONLY_DEPLOYMENT.md). No out-of-the-box experience,
general security sandbox, or production use is promised. This is an experimental, educational
engineering tool; outputs are theoretical results under explicit assumptions and are not a substitute
for final engineering design review.
